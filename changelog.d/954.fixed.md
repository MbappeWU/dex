**`transform plan` measures a model that builds rows from an inline `VALUES` list.** A comparison mart that forms its windows with `cross join (values (7), (28)) as windows (window_days)` had every change on it reported as `attributed: false` with "unsupported FROM source: Values", because the query firewall knew no such source. A named, literal-only `VALUES` list reads nothing from the warehouse, so the firewall now admits it beside tables, views and CTEs, and the model's predicate, join and `GROUP BY` changes get their measured `rows` and `delta`. Only plain literals are admitted in its rows (numbers, strings, `NULL` and booleans): a list whose rows hold an expression (a typed literal such as `DATE '2020-01-01'` counts as one), a column or a subquery, or whose columns are unnamed, is still refused.
