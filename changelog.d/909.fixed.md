**`transform init` renders the committed build identity, not the role dex reads with.** Where a committed `postgres.user`/`redshift.user` names a build role different from the one dex's own connection discovery found (a read-only `dex_ro` in `DATABASE_URL`, say), init used to render dex's read role into `profiles.yml`, and the first `transform build` then refused with a hint to grant that read-only role CREATE; that quietly removed the read/write split the docs ask for. The committed user now wins, init notes where the two identities differ, and a build preflight refusal about a role the profile names but the config does not points at the committed identity before offering any grant.
