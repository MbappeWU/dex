**Refactor comparison for two compiled SELECTs.** `transform.compare_refactors` records the baseline and proposed identities, the input scope, and the comparison time. It compares output column names and DuckDB types, with an optional mapping from baseline names to proposed names, and runs the row multiset only when those schemas match. A declared key that is present on the output also returns counts of keys that are missing, added, or changed. A query DuckDB cannot run, or an output this comparator cannot check, comes back `not_checked` with a reason. `equivalent` means the two statements matched on the inputs that were compared. `compare_selects` is unchanged.
